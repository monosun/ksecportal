# KSecPortal v1.35.0 릴리즈 노트

**릴리즈 일자**: 2026-08-16

ISMS-P 통제항목에 보안정책을 연결할 때 **장(章) 전체뿐 아니라 조(條) 하나만 지목**할 수 있게 되었습니다.
v1.34.0 에서 정책을 **지침 > 장 > 조** 3단으로 세분화한 것을 매핑까지 이어 붙인 변경으로,
인증 심사에서 통제항목의 근거 조문을 바로 제시할 수 있습니다.

함께 **알기쉬운 보안사례집** 메뉴가 새로 생겼고, 목록 화면이 **모니터 화면 높이에 맞게** 표시됩니다.

---

## 1. ISMS-P 통제항목 매핑 — 조(條) 단위 연결

`1.1.1 경영진의 참여` 에 `개인정보보호 지침 - 제1장 총칙` 을 통째로 거는 대신
그 장의 **`제4조(최고경영자의 책임)` 한 조만** 매핑할 수 있습니다.

- 통제항목을 펼치면 나오는 **정책 추가** 목록에서, 정책 이름을 누르면 **장 전체**가 매핑됩니다.
- 오른쪽 **`조 N`** 버튼을 누르면 그 장의 **조 목록이 펼쳐지고**, 조를 클릭하면 그 조만 매핑됩니다.
  조 목록은 한 번 불러오면 캐시되고, 조가 세분화되지 않은 정책에는 버튼이 나타나지 않습니다.
- **한 장에 장 전체와 여러 조를 동시에** 걸 수 있습니다. 매핑 후에도 목록이 닫히지 않아 여러 건을 이어서 추가합니다.
- 이미 걸린 항목은 `매핑됨` 으로 표시되고 다시 눌리지 않습니다. 정책 이름 아래에 `· 조 N건 매핑됨` 으로 현황이 보입니다.
- 후보 목록에서 **이미 매핑된 장을 빼지 않습니다.** 장 전체를 건 뒤에도 그 안의 조를 따로 골라야 하기 때문입니다.

## 2. 매핑 현황 — 장으로 묶어 보기

왼쪽 **매핑된 정책**이 **장 기준으로 묶여** 표시됩니다.

- 장 이름 옆 **`장 전체`** 배지는 그 장을 통째로 매핑했다는 뜻이고, 그 아래 **주황색 칩**이 조 단위 매핑입니다.
- **× 버튼은 각각 따로 동작합니다.** 장 전체의 × 는 장 매핑만, 조 칩의 × 는 그 조만 지웁니다.
  **장 전체를 해제해도 같은 장의 조 매핑은 그대로 남습니다.**
- 장 이름·조 칩을 클릭하면 **정책 내용 미리보기**가 열리며, 조 칩으로 열면 **그 조가 펼쳐진 상태**로 보입니다.
- 목록 화면 `매핑 정책` 칸은 장 매핑이 **남색**, 조 매핑이 **주황색**(`제1장 제4조` 형태)으로 구분됩니다.

## 3. 정책 본문을 고쳐도 매핑이 유지됩니다

기존에는 정책을 저장할 때마다 조 레코드를 **지우고 새로 만들었습니다.** 조 id 가 매번 바뀌므로,
본문을 한 글자만 고쳐도 그 장에 걸린 **조 매핑이 통째로 사라지는** 문제가 있었습니다.

- 이제 조 표기(`제4조`) 기준으로 **기존 조 레코드를 재사용**하고 제목·본문·정렬만 갱신합니다.
- 본문에서 **없어진 조만** 삭제되며, 그 조에 걸린 매핑도 함께 정리됩니다(`ON DELETE CASCADE`).
- 같은 표기가 여러 번 나오는 문서도 표기별 순서대로 짝지어 재사용합니다.
- 정책 수정·엑셀 일괄 등록·**조문 재등록** 모두 같은 경로를 타므로 동작이 일치합니다.

## 4. 알기쉬운 보안사례집 (신규 메뉴)

**보안 가이드 및 자료 › 보안용어집** 아래에 **알기쉬운 보안사례집** 메뉴가 생겼습니다.
어려운 보안 개념을 실제 업무 상황으로 풀어 놓은 자료로, 두 개의 탭으로 나뉩니다.

| 탭 | 대상 | 내용 |
|----|------|------|
| **어려운 보안, 쉽게 이해하기** | 전 임직원 | 피싱·비밀번호 재사용·MFA·세션 탈취·권한 분리·인증과 인가·API Key·로그 속 개인정보·SQL 인젝션·생성형 AI 등 **11개 사례** |
| **경영진 보안 투자 사례** | 경영진 보고 담당자 | 보안 투자 질문 **15선**과 예산 확보 7원칙·인력 확보 논리·이사회 1페이지 템플릿·자주 나오는 질문 등 **36개 항목**(Part 1~7 그룹) |

- 사례는 **카드 목록**으로 보이고(번호 배지·제목·첫 문단 요약), 클릭하면 **상세 팝업**에 전문이 뜹니다.
- 팝업에서 **`‹ 이전 사례` / `다음 사례 ›`** 버튼과 **← / →** 키로 앞뒤 사례를 넘깁니다. `Esc` 로 닫습니다.
- **검색은 제목뿐 아니라 본문 전체**를 훑고, 검색 중에는 팝업의 앞뒤 이동도 결과 안에서만 움직입니다.
- 본문은 **`docs/security-cases-basic.md` · `docs/security-cases-executive.md` 가 단일 원본**입니다.
  프론트엔드 이미지 빌드 때 `public/help/` 로 복사되며 **DB를 쓰지 않습니다** — 내용을 고치려면
  두 파일을 수정하고 프론트엔드만 다시 빌드하면 됩니다. 머리글 구조(`# 사례 제목`,
  `# Part N.` + `## 항목`)만 지키면 항목 카드가 자동으로 다시 만들어집니다.

> **RBAC** — 메뉴 키 `security_cases` 가 추가되었습니다. MANAGER 는 기동 시 자동 보충되고 ADMIN 은 전 메뉴를 봅니다.
> **일반 임직원(USER) 은 기존 인스턴스에서 자동으로 열리지 않습니다** — 관리 > 권한관리에서 읽기 권한을 켜 주세요.
> (신규 설치는 USER 기본 권한에 포함됩니다)

## 5. 목록을 모니터 화면 크기에 맞게 표시

한 페이지 건수가 20건으로 고정돼 있어 **큰 모니터에서는 표 아래가 비고, 노트북에서는 목록이 잘려**
스크롤해야 했습니다. 이제 표가 시작되는 위치부터 창 아래까지 남는 높이를 재서
**한 화면에 들어가는 만큼만** 불러옵니다.

- 적용 화면: **보안 정책(장 목록·조문 검색) · 자산관리 · 인시던트 · 취약점 · 보안성 심의 · 소스 취약점 점검 · SBOM · 사용자관리 · 문제은행**
  창 크기를 바꾸면 다시 계산하며, 보고 있던 **첫 행 순번은 유지**합니다.
- 건수를 직접 고를 수 있는 화면(**감사 로그 · 성능관리 · 보안문서 · 위험평가 · 위험처리**)은
  **기본값만** 화면 높이에 맞추고 사용자가 고른 값은 그대로 둡니다.
  위험평가·위험처리 목록에는 **`화면 맞춤`** 선택지가 추가되었습니다.
- 행 높이·표 머리글 위치는 화면마다 다르므로 **실제로 그려진 DOM 을 재서** 계산합니다
  (`frontend/src/composables/useFitPageSize.js`).

## 6. 화면 정리

- **대시보드 › 보안법령정보 뉴스 목록** — 항목 사이 여백이 지나치게 넓던 문제를 줄였습니다.
  요약이 제목과 같아 감춰지는 피드(구글 뉴스 계열, 개인정보 유출뉴스 등)는 제목 한 줄만 남으므로
  더 좁은 여백을 적용해, 같은 높이에 더 많은 기사가 들어옵니다.

## API 변경

| 메서드 | 경로 | 설명 |
|--------|------|------|
| POST | `/api/isms/items/:itemId/articles/:articleId` | 조 단위 매핑 — 소속 장은 조에서 따라간다 *(MANAGER+)* |
| DELETE | `/api/isms/items/:itemId/articles/:articleId` | 조 매핑 해제 *(MANAGER+)* |

- `DELETE /api/isms/items/:itemId/policies/:policyId` 는 이제 **장 전체 매핑만** 해제합니다(조 매핑은 유지).
- `GET /api/isms/items` 응답의 `mappedPolicies[]` 에 `guidelineName` · `chapterLabel` · `chapterTitle` ·
  `articleId` · `articleLabel` · `articleTitle` · `articleDisplayName` 이 추가되었습니다.
  `articleId` 가 `null` 이면 장 전체 매핑입니다. 정렬은 **정책 id → 장 전체 → 조** 순입니다.

> 같은 장에 장 전체와 여러 조가 함께 올 수 있으므로 **`id`(정책 id) 하나로는 항목을 구분할 수 없습니다.**
> 응답을 직접 소비하는 코드가 있다면 키를 `articleId` 까지 조합하도록 고쳐야 합니다.

## DB 변경

| 대상 | 내용 |
|------|------|
| `isms_policy_mappings` | `policy_article_id` 컬럼 추가(NULL = 장 전체), FK `fk_ipm_policy_article` (`ON DELETE CASCADE`) |
| `isms_policy_mappings` | 유니크 제약을 `(isms_item_id, policy_id)` → **`(isms_item_id, policy_id, policy_article_id)`** 로 교체 |

> **마이그레이션 필수** — `db/migration/v1.58.0_isms_article_mapping.sql`
> `ddl-auto: update` 는 컬럼만 추가할 뿐 **기존 유니크 제약을 지우지 못합니다.** 제약이 남아 있으면
> 같은 장의 **두 번째 조를 매핑할 때 `Duplicate entry` 로 실패**합니다.
> 스크립트는 컬럼·새 유니크·FK 를 만든 뒤 옛 제약을 찾아 지우며, **여러 번 실행해도 안전**합니다.
> (제약 이름이 환경마다 다를 수 있어 `information_schema` 에서 동적으로 찾습니다)

```bash
docker compose exec -T db mysql -usecportal -psecportal123 secportal < db/migration/v1.58.0_isms_article_mapping.sql
```

## 업그레이드

```bash
git pull
docker compose build backend frontend
docker compose exec -T db mysql -usecportal -psecportal123 secportal < db/migration/v1.58.0_isms_article_mapping.sql
docker compose up -d backend frontend
```

- 마이그레이션 전에 **DB 백업**을 권장합니다.
- 배포 후 브라우저 **하드 새로고침(Ctrl+Shift+R)** 이 필요합니다.
- 기존 매핑은 모두 **장 전체 매핑**(`policy_article_id = NULL`)으로 그대로 유지됩니다.
- 조 목록이 비어 있는 정책은 본문을 `### 제N조(제목)` 형식으로 정리한 뒤
  보안 정책 화면에서 **조문 재등록**을 실행하세요.
