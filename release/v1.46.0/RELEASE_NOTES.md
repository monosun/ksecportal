# KSecPortal v1.46.0 릴리즈 노트

**릴리즈 일자**: 2026-11-11

**[보안 강화]** 공격 탐지에 **타르핏**과 **미끼 데이터 재사용 탐지**를 더하고, 화면 파일에 **무결성 검증(SRI)** 을 적용합니다.

---

## 1. 타르핏 — 차단 IP 에 지연 + 가짜 데이터 응답 (기본값)

차단된 IP 를 바로 403 으로 끊으면 공격자는 차단을 알아채고 IP 를 바꿉니다. 이제 기본 응답 방식은 **타르핏**입니다.

| 요청 | 응답 |
|------|------|
| 조회(`GET`) | 3~15초 무작위 지연 후 그럴듯한 **가짜 목록·상세**(기본 50건, 전체 수천 건으로 표시) |
| 쓰기 | 지연 후 일시 오류(503) — 실제 데이터 변경 없음 |
| 로그인·MFA | 지연 후 로그인 실패(401) |
| 다운로드·내보내기·미리보기 | 지연 후 404 |

- 자동화 도구·AI 에이전트가 차단된 줄 모르고 가짜 데이터를 처리하느라 시간과 토큰을 씁니다.
- 대기는 서블릿 비동기 처리로 해서 작업 스레드를 점유하지 않습니다. IP 당 동시 4건·전체 200건을 넘으면 지연 없이 503 으로 응답합니다.
- 설정: **보안 운영 > 공격 탐지 > 설정** 의 *차단 IP 응답 방식*(타르핏/즉시 차단), 최소·최대 지연(최대 20초), 미끼 목록 건수.
- 개요 탭의 *차단 중인 IP* 카드에 기동 이후 타르핏 응답 건수를 표시합니다.

## 2. 미끼 데이터 재사용 탐지 (신규 유형 `HONEY_DATA`, 심각)

- 가짜 레코드의 ID 는 서버 비밀 키(`detection.honey_data_secret`, 처음 기동할 때 자동 생성되고 화면·API 로 내보내지 않음)로 서명합니다. 실제 ID 와 겹치지 않는 대역입니다.
- 이 ID 가 요청 경로·쿼리에 다시 나타나면 차단 해제 후 또는 다른 IP·계정에서 수집 데이터를 재사용한 것으로 보고 **심각** 이벤트를 남기고 그 IP 를 자동 차단합니다. 로그인 계정이 있으면 이벤트에 기록됩니다.
- 가짜 데이터의 담당자 이메일 일부에 미끼 계정을 섞어, 그 계정으로 로그인을 시도해도 탐지됩니다.

## 3. 화면 파일 무결성 검증(SRI)

- 빌드 시 `index.html` 의 스크립트·스타일에 `integrity="sha384-…"` 를 넣습니다. 전송 구간에서 파일이 바뀌면 브라우저가 실행을 거부합니다.
- 사용자가 자기 브라우저에서 화면을 고치는 것은 막지 못합니다. 권한 검사는 항상 서버에서 합니다.
- HSTS 는 HTTP 로 운영 중이면 브라우저가 무시하므로, HTTPS 를 적용한 뒤 `nginx/nginx.conf` 의 주석을 해제하세요.

## 4. 주의

- 오탐으로 차단된 실제 사용자는 가짜 데이터를 보게 됩니다. 자동 차단 기준 심각도는 기본값(**심각**)을 유지하길 권장합니다. 사용자가 "데이터가 이상하다"고 문의하면 **차단 IP** 탭을 먼저 확인하세요.
- 이전처럼 즉시 403 을 원하면 설정에서 응답 방식을 **즉시 차단**으로 바꾸세요.

## 5. 업그레이드

```bash
docker compose build backend frontend
docker compose up -d backend frontend
```

DB 변경 없음(새 설정 키는 기본값으로 동작하고, 이벤트 유형 컬럼은 VARCHAR 라 마이그레이션 불필요). 배포 후 브라우저 강력 새로고침(Ctrl+Shift+R)이 필요합니다.
