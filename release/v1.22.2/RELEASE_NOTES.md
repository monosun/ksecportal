# v1.22.2 릴리즈 노트

**릴리즈 일자**: 2026-07-25

권한관리에서 **메뉴 권한을 저장하면 실패하던 문제**와, **업그레이드로 새로 추가된 메뉴가 MANAGER에게 보이지 않던 문제**를 수정했습니다.

## 버그 수정

### 1. 메뉴 권한 저장이 실패함 (권한관리)

**증상**
권한관리에서 기본 역할(MANAGER·USER) 또는 사용자 지정 Role의 메뉴 권한을 체크하고 저장하면 실패했습니다.
이미 권한이 있는 상태에서 저장할 때(예: MANAGER에 메뉴 두 개를 추가로 켜고 저장) 항상 재현됩니다.

```
Duplicate entry '1-dash_risks' for key 'role_permissions.uk_role_menu'
```

**원인**
권한 저장 로직이 **기존 권한 행을 모두 지우고 요청 내용을 새로 넣는** 방식이었습니다.

```java
role.getPermissions().clear();
applyPermissions(role, req.getPermissions());
```

`role_permissions` 에는 `(role_id, menu_key)` 유니크 제약(`uk_role_menu`)이 있는데, Hibernate 는 flush 시
**INSERT 를 DELETE 보다 먼저** 실행합니다. 그래서 유지되는 메뉴(위 예에서 `dash_risks`)를 다시 INSERT 하는 순간
아직 지워지지 않은 기존 행과 충돌했습니다.

MANAGER 기본 역할은 처음부터 전 메뉴 권한을 갖고 있어 **저장할 때마다 확실히 충돌**했고,
사용자 지정 Role도 기존 메뉴를 유지한 채 수정하면 같은 오류가 났습니다(이전부터 있던 잠재 결함).

**수정**
권한을 지우고 다시 넣지 않고 **제자리에서 맞추도록** 바꿨습니다.

1. 요청에 없는 메뉴 → 제거
2. 유지되는 메뉴 → 읽기·쓰기·삭제 **값만 갱신**
3. 요청에만 있는 메뉴 → 새로 추가

기본 역할과 사용자 지정 Role이 같은 로직을 쓰므로 양쪽 모두 해결됩니다. 같은 메뉴 키가 요청에 중복으로 와도 마지막 값만 반영합니다.

### 2. 새로 추가된 메뉴가 MANAGER에게 보이지 않음

**증상**
v1.19.0 **운영현황관리**, v1.21.0 **보안용어집** 을 추가한 뒤에도 MANAGER 계정에서 두 메뉴가 보이지 않았습니다.

**원인**
기본 역할 권한 시더는 **행이 비어 있을 때만** 동작합니다(관리자가 수정한 내용을 재기동 때 되돌리지 않기 위해).
그래서 v1.18.0 에서 42개 메뉴로 한 번 생성된 뒤에는, 이후 릴리즈에서 늘어난 메뉴 키가 MANAGER 권한 행에 반영되지 않았습니다.

**수정**
기동 시 MANAGER 기본 역할에 **없는 메뉴 키만** 읽기·쓰기·삭제로 보충합니다.

- MANAGER 는 "기본적으로 전 메뉴 사용"이 전제이므로 새 메뉴는 자동으로 열립니다.
- **관리자가 의도적으로 끈 메뉴는 행이 남아 있어 다시 켜지지 않습니다** — 새로 생긴 메뉴만 대상입니다.
- USER 기본 역할은 최소 권한이 기본값이라 보충하지 않습니다.

업그레이드 시 로그로 확인할 수 있습니다.

```
[RBAC] MANAGER 기본 역할에 신규 메뉴 2개 보충: [operation_status, glossary]
```

## 영향 범위

- 백엔드 로직만 변경되었습니다. **스키마 변경은 없습니다.**
- 이번 기동으로 MANAGER 기본 역할 권한이 42개 → **44개**(전 메뉴)로 보충됩니다. 따라서 MANAGER 계정은 **별도 설정 없이** 운영현황관리·보안용어집을 사용할 수 있습니다.
- 특정 메뉴를 MANAGER에게 감추려면 권한관리 > 기본 역할 권한에서 해당 메뉴를 해제하십시오(이제 정상 저장됩니다).
