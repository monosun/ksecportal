# KSecPortal v1.34.0 릴리즈 노트

**릴리즈 일자**: 2026-08-16

보안 정책을 **지침 > 장(章) > 조(條)** 3단 구조로 다루도록 바꾸고, **조 단위 조문 검색**을 추가했습니다.
ISMS-P 이행점검에서는 증적 팝업을 닫지 않고 **앞뒤 통제항목으로 바로 이동**할 수 있으며, 통제항목-정책 매핑에서 **정책이 10건까지만 보이던 문제**를 해결했습니다.

---

## 1. 보안 정책 — 지침 · 장 · 조 구조 세분화

정책 1건을 **장(章)** 으로 보고, 본문의 `### 제1조(목적)` 머리글을 **조(條) 단위 레코드로 자동 세분화**해 저장합니다.

- 제목을 `개인정보보호 지침 - 제1장 총칙` 형식으로 쓰면 **지침명·장 번호·장 제목**이 자동 분리되어 정규화 컬럼에 저장됩니다. 번호가 없는 **부칙**도 장으로 인식하고, 정렬 시 항상 맨 뒤로 갑니다.
- 조 제목 뒤의 `<개정 2024.5.28>` 같은 표기는 **개정 표기(note)** 로 따로 보관해 조 옆에 표시합니다. `제3조의2` 같은 **가지번호**도 인식합니다.
- 조 머리글이 하나도 없는 문서는 본문 전체를 **"전문"** 한 건으로 보존하므로, 형식이 다른 기존 문서도 검색에서 빠지지 않습니다. 첫 조 앞의 도입부도 "전문"으로 남습니다.
- 조는 본문의 **파생 데이터**입니다. 정책을 등록·수정하거나 **엑셀 일괄 등록**하면 그때마다 다시 세분화되어 본문과 항상 일치합니다.
- 목록 화면에 `지침` · `장` · `조 N개` 컬럼이 추가되었습니다.

> 기존에 등록된 정책은 **최초 기동 시 자동으로 세분화**됩니다(`PolicyArticleInitializer` — 조 테이블이 비어 있을 때만 동작하는 seed-when-empty 방식). 조가 이미 있는데 지침/장 값만 비어 있는 데이터는 해당 정책만 보정합니다.

## 2. 보안 정책 — 조문 검색 탭

**보안 정책** 화면 상단이 **`장 목록` / `조문 검색`** 두 탭으로 나뉩니다. 조문 검색 탭에서 조 단위로 찾습니다.

| 검색 범위 | 찾는 대상 |
|-----------|-----------|
| 전체 (제목+본문) | 조 제목·본문·지침명·장 제목·조 표기 모두 |
| 본문 내용 | 조 본문과 개정 표기 |
| 조 제목 | 조 제목만 (예: `접속기록`) |
| 지침명 | 지침 이름만 |
| 장 제목 | 장 표기·제목 (예: `총칙`) |
| 조 표기 (제N조) | `제31조` 같은 조 번호 표기 |

- **지침 → 장 → 조 번호** 로 범위를 좁힐 수 있습니다. 지침을 고르면 그 지침의 장 목록만 나타나고, 지침을 바꾸면 장 선택은 초기화됩니다. 카테고리·상태 필터도 함께 적용됩니다.
- 결과는 `지침 › 장` 경로와 함께 표시되고, **검색어와 일치하는 부분이 노란색으로 강조**됩니다. 접힌 상태에서는 검색어 주변 본문이 미리보기로 보입니다.
- 정렬은 **지침 → 장 번호 → 조 번호** 로 고정입니다.
- 결과를 펼친 뒤 **소속 장 전체 보기**를 누르면 그 장의 상세 팝업이 열립니다.
- **조문 재등록**(MANAGER 이상) — DB에서 본문을 직접 손봤을 때처럼 조가 본문과 어긋난 경우 전체 정책을 다시 파싱합니다. 감사 로그에 `POLICY_ARTICLE_RESYNC` 로 남습니다.

## 3. 보안 정책 — 상세 팝업 조문별 보기

정책 상세 팝업에서 **`조문별 보기` / `전체 원문`** 을 전환합니다.

- **조문별 보기**(기본): 조를 접이식 목록으로 표시하고 **모두 펼치기 / 모두 접기**를 지원합니다.
- **전체 원문**: 기존과 동일하게 장 본문 전체를 이어서 봅니다.
- 조가 인식되지 않은 문서는 전환 없이 전체 원문만 표시하며, **조문 조회가 실패해도 원문 보기는 그대로 동작**합니다.

## 4. ISMS-P 이행점검 — 증적 팝업에서 이전/다음 항목 이동

통제항목 증적 팝업을 닫았다 다시 열지 않고 **앞뒤 항목으로 바로 이동**합니다.

- 팝업 아래쪽 **`이전 항목` / `다음 항목`** 버튼과 제목 오른쪽 **`‹ 3 / 101 ›`** 화살표를 제공합니다.
- 키보드 **← / →** 키로도 이동합니다. **입력란에 글을 쓰는 중에는 방향키를 가로채지 않으며**, `Esc` 로 닫힙니다.
- 이동 순서는 **현재 목록에 적용된 필터 순서 그대로**입니다. 영역 탭·상태 필터·검색어를 걸어 두면 그 결과 안에서만 이동합니다.
- 처음/마지막 항목에서는 해당 방향 버튼이 비활성화됩니다.

## 5. ISMS-P 통제항목 매핑 — 정책 후보 전체 노출 · 지침/장 검색

**통제항목 매핑** 화면에서 정책을 연결할 때 후보가 **10건까지만 보이던 제한을 없앴습니다.**

- 검색창을 클릭하면 **매핑 가능한 정책 전체**가 스크롤 목록으로 열리고, 맨 위에 `매핑 가능한 정책 N건` 이 고정 표시됩니다. 정책 수가 늘면서 뒤쪽 지침의 장이 아예 보이지 않던 문제를 해결합니다.
- 검색어는 **정책 제목뿐 아니라 지침명·장 표기·장 제목**으로도 찾습니다. (예: `총칙`, `개인정보보호 지침`)
- 검색어 없이 후보가 없을 때도 `추가할 수 있는 정책이 없습니다` 로 상태를 알려 줍니다.

## API 변경

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/policies/articles` | 조문 검색 (`keyword` · `scope` · `guideline` · `chapterNo` · `policyId` · `articleNo` · `status` · `category`) |
| GET | `/api/policies/articles/facets` | 검색 필터용 지침 > 장 목록 |
| GET | `/api/policies/:id/articles` | 해당 장의 조 목록 |
| POST | `/api/policies/articles/resync` | 조문 재등록 (MANAGER+) |

- `GET /api/policies` 응답에 `guidelineName` · `chapterNo` · `chapterLabel` · `chapterTitle` · `articleCount` 가 추가되었습니다. 조 개수는 페이지 단위 집계 쿼리 1회로 조회합니다.
- `GET /api/policies/:id` 응답에도 지침/장 필드가 추가되었습니다. 기존 필드는 그대로라 **하위 호환됩니다.**

## DB 변경

| 대상 | 내용 |
|------|------|
| `policies` | `guideline_name` · `chapter_no` · `chapter_label` · `chapter_title` 컬럼과 `idx_policies_guideline` 인덱스 추가 |
| `policy_articles` | **신규 테이블** — 조 번호·가지번호·표기·제목·개정 표기·본문·정렬 순서. 정책 삭제 시 `ON DELETE CASCADE` |

> **마이그레이션** — `db/migration/v1.57.0_policy_articles.sql`
> `ddl-auto: update` 가 새 컬럼·테이블은 기동 시 자동으로 추가하므로 **적용하지 않아도 동작**하지만, 백엔드를 올리기 전에 스키마를 미리 맞추려면 이 스크립트를 사용하세요.
> 백엔드를 이미 기동한 환경에서 실행하면 `Duplicate column` 으로 실패합니다 — 이미 반영된 상태이므로 건너뛰면 됩니다. 조 데이터는 기동 시 초기화기가 채웁니다.

## 업그레이드

```bash
git pull
docker compose build backend frontend
docker compose up -d backend frontend
```

- 배포 후 브라우저 **하드 새로고침(Ctrl+Shift+R)** 이 필요합니다.
- 기동 로그에 `보안정책 조문 세분화 완료 — 정책(장) N건 → 조 M건` 이 남으면 세분화가 끝난 것입니다.
- 조문이 기대와 다르게 나뉘면 정책 제목을 `지침명 - 제N장 장제목` 형식으로, 조 머리글을 `### 제N조(제목)` 형식으로 정리한 뒤 **조문 재등록**을 실행하세요.
