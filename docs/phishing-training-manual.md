## 1. 개요

**모의 훈련**은 다음 4개 탭으로 구성됩니다. (메뉴: **교육 및 훈련 › 모의 훈련**)

| 탭 | 역할 |
|----|------|
| **악성메일 템플릿** | 발송할 피싱 메일 본문·제목·발신자를 등록·관리 |
| **발송대상 관리** | 훈련 메일을 받을 임직원 목록 관리 |
| **모의훈련 현황** | 템플릿 + 대상자를 묶어 캠페인으로 발송·추적 |
| **발송 로그** | 대상자별 실제 발송 성공/실패 및 열람·클릭 결과 |

훈련 흐름은 **템플릿 준비 → 대상자 등록 → 캠페인 생성 → 실시(발송) → 열람·클릭 자동 추적 → 결과 분석**입니다.

## 2. 사전 준비 (필수)

훈련 메일이 실제로 발송되고 반응이 추적되려면 아래 두 가지 설정이 **반드시** 선행되어야 합니다. 하나라도 누락되면 발송 실패 또는 열람/클릭 미기록이 발생합니다.

### 2.1 발송 메일서버(SMTP) 설정

**관리 › 설정관리 › 시스템 설정 탭 › 발송 메일서버(SMTP) 설정**

| 항목 | 설명 |
|------|------|
| SMTP 호스트 / 포트 | 사용하는 메일 서버 (예: `smtp.gmail.com` / `587`) |
| 계정 / 비밀번호 | **실제** 발송 계정 자격증명 |
| 발신자 주소(From) / 표시 이름 | 수신자에게 보이는 발신 정보 |
| SMTP 인증 사용 / STARTTLS 사용 | 서버 정책에 맞게 설정 (일반적으로 둘 다 켬) |
| **이 설정 사용** | 반드시 **체크**해야 이 설정으로 발송됩니다 |

저장 후 **테스트 메일 발송**으로 정상 수신을 확인하세요.

> ⚠️ **주의**
> - **Gmail은 계정 비밀번호로 인증되지 않습니다.** 2단계 인증을 켠 뒤 발급하는 **앱 비밀번호(16자리)** 를 사용하고, 계정은 전체 이메일 주소를 입력하세요.
> - **465(암시적 SSL) 포트는 지원하지 않습니다.** STARTTLS 방식의 **587** 포트를 사용하세요.
> - "이 설정 사용"을 끄면 서버 환경변수(`MAIL_*` / `APP_BASE_URL`) 기본값으로 폴백하며, 기본값은 예시용이라 인증 실패(`Authentication failed`)가 납니다.

### 2.2 이메일 발송 링크 도메인 주소

**관리 › 설정관리 › 시스템 설정 탭 › 승인 알림 설정 › 이메일 발송 링크 도메인 주소** (`app.base_url`)

훈련 메일에 포함되는 **열람·클릭 추적 링크의 기준 주소**입니다.

- 임직원이 **실제로 접속 가능한 외부 주소**를 입력해야 합니다. 예: `https://sec.example.com`
- 도메인만 입력하면 `/api` 경로가 자동으로 붙습니다.
- 비워두면 서버 환경변수 `APP_BASE_URL`(기본 `http://localhost:8080/api`)을 사용하는데, 이 경우 사내 테스트 외에는 **추적 링크가 동작하지 않습니다**(수신자 브라우저에서 접속 불가).

## 3. 전체 흐름

```
[관리자]                                    [대상 임직원]
   │
   │ 1. 템플릿 작성 (제목·발신자·본문 HTML)
   │ 2. 발송대상 등록
   │ 3. 캠페인 생성 (템플릿 + 대상자 선택)   상태: DRAFT
   │
   │ 4. 캠페인 "실시" ──────────────────────▶ 메일 수신
   │    · 대상자별 고유 토큰 부여               │
   │    · 본문 변수 치환 후 SMTP 발송           │
   │      상태: RUNNING                        │ 5. 메일 열람 ──▶ 추적 픽셀 로드
   │                                          │                 → opened_at 기록
   │                                          │ 6. 링크 클릭 ──▶ /track/../click
   │                                          │                 → clicked_at 기록
   │                                          │                 → 피싱 인식 안내 페이지로 이동
   │ 7. 결과 조회·분석                          │
   │ 8. 캠페인 "완료"  상태: COMPLETED
```

## 4. 악성메일 템플릿 관리

**교육 및 훈련 › 모의 훈련 › 악성메일 템플릿** 탭에서 **+ 템플릿 추가** 버튼으로 등록합니다. 설치 시 카테고리·난이도별 **기본 예제 10종**이 제공됩니다.

### 4.1 입력 항목

| 항목 | 필수 | 설명 |
|------|:---:|------|
| 템플릿명 | ● | 관리용 이름 (수신자에게는 보이지 않음) |
| 카테고리 | ● | IT · HR · DELIVERY · FINANCE · SECURITY · MARKETING · 기타 |
| 난이도 | | 쉬움(EASY) · 보통(MEDIUM) · 어려움(HARD) — 결과 분석용 분류 |
| 메일 제목 | ● | 수신자에게 표시되는 제목 |
| 발신자 이름 / 이메일 | ● | 위장할 발신자 (예: `IT 지원팀`) |
| 메일 본문 (HTML) | ● | 인라인 스타일 HTML. 아래 치환 변수 사용 |
| 설명 | | 템플릿 목적 메모 |

### 4.2 치환 변수

본문에 아래 변수를 **문자열 그대로** 적어두면, 캠페인 실시(발송) 시점에 시스템이 **대상자별로 자동 치환**합니다. 별도로 값을 지정할 필요가 없습니다.

| 변수 | 치환 내용 | 사용 위치 |
|------|-----------|-----------|
| `{TARGET_NAME}` | 대상자 이름 | 본문 아무 곳 |
| `{TARGET_EMAIL}` | 대상자 이메일 | 본문 아무 곳 |
| `{CLICK_URL}` | 클릭 추적 링크 | 버튼·링크의 `href` |
| `{OPEN_URL}` | 열람 추적 픽셀 URL | 숨김 이미지의 `src` |

> ⚠️ 치환은 **본문(HTML)에서만** 이루어집니다. **메일 제목·발신자 항목에 변수를 넣으면 치환되지 않고 문자 그대로 발송**되므로 사용하지 마세요.

### 4.3 {CLICK_URL} · {OPEN_URL} 은 어떻게 만들어지나

이 두 URL은 **직접 만들지 않습니다.** 발송 시 시스템이 대상자마다 고유 추적 토큰을 부여해 아래 형태로 자동 생성합니다.

```
{CLICK_URL} → {도메인}/api/phishing/track/{대상자별 고유토큰}/click
{OPEN_URL}  → {도메인}/api/phishing/track/{대상자별 고유토큰}/open
```

- `{도메인}` = [2.2 이메일 발송 링크 도메인 주소](#22-이메일-발송-링크-도메인-주소)에서 설정한 값
- 고유 토큰(`tracking_token`)은 대상자마다 다르므로, **누가** 열람·클릭했는지 식별됩니다.

### 4.4 본문 작성 팁

- 메일 클라이언트 호환을 위해 **인라인 스타일**(`style="…"`)을 사용합니다. 외부 CSS·스크립트는 대부분 차단됩니다.
- 클릭 유도 버튼의 `href`에는 반드시 `{CLICK_URL}` 을 넣습니다.
- 본문 맨 끝에 열람 추적 픽셀을 **숨김 이미지**로 포함합니다.

```html
<div style="font-family:'Malgun Gothic',Arial,sans-serif;max-width:600px;margin:0 auto;padding:20px">
  <p>{TARGET_NAME}님, 안녕하세요.</p>
  <p>보안 정책에 따라 비밀번호를 재설정해야 합니다.</p>

  <!-- 클릭 유도 버튼 -->
  <div style="text-align:center;margin:30px 0">
    <a href="{CLICK_URL}"
       style="background:#1a56db;color:#fff;padding:12px 28px;border-radius:6px;
              text-decoration:none;font-weight:bold">비밀번호 재설정</a>
  </div>

  <!-- 열람 추적 픽셀 (본문 맨 끝, 눈에 보이지 않음) -->
  <img src="{OPEN_URL}" width="1" height="1" style="display:none" alt="">
</div>
```

### 4.5 기본 제공 예제 10종

| 카테고리 | 난이도 | 이름 |
|----------|--------|------|
| IT | 보통 | 메일함 용량 초과 경고 |
| IT | 쉬움 | 계정 비밀번호 만료 안내 |
| HR | 보통 | 이달의 급여명세서 확인 |
| HR | 쉬움 | 연차 신청 승인 요청 |
| FINANCE | 어려움 | 전자세금계산서 발급 확인 |
| DELIVERY | 보통 | 택배 배송 상태 확인 |
| SECURITY | 어려움 | 비정상 로그인 시도 감지 |
| MARKETING | 쉬움 | 사내 복지몰 경품 당첨 안내 |
| SECURITY | 어려움 | 다중인증(MFA) 재등록 요청 |
| 기타 | 보통 | 복지제도 개선 설문 참여 요청 |

> 예제 10종은 템플릿이 **하나도 없을 때만** 자동 생성됩니다(seed-when-empty). 모두 삭제하면 다음 기동 시 다시 채워집니다.

## 5. 발송대상 관리

**발송대상 관리** 탭에서 훈련 메일을 받을 임직원을 등록합니다.

| 항목 | 필수 | 설명 |
|------|:---:|------|
| 이름 | ● | 대상자 이름 (`{TARGET_NAME}`으로 치환) |
| 이메일 | ● | 수신 주소 (`{TARGET_EMAIL}`으로 치환) |
| 부서 / 직급 | | 결과 분석·집계용 |
| 활성(active) | | **활성** 대상만 캠페인에서 선택·발송 대상이 됩니다. 목록 토글로 사용/미사용 전환 |

- 대상자 이름·이메일은 **개인정보 마스킹 기준**에 따라 목록에서 가려서 표시됩니다.
- 퇴사자 등은 삭제 대신 **비활성**으로 두는 것을 권장합니다(과거 캠페인 이력 보존).

## 6. 모의훈련 캠페인

**모의훈련 현황** 탭에서 **+ 캠페인 생성**으로 만듭니다.

### 6.1 생성

1. 캠페인명 입력
2. **템플릿 선택** (악성메일 템플릿 중 1개)
3. **발송 예정일시**(선택) 및 설명 입력
4. **발송 대상 선택** — 최소 1명 이상 (미선택 시 저장 불가)
5. 저장 → 상태 **DRAFT**

생성 시 선택한 대상자마다 고유 추적 토큰이 미리 부여됩니다.

### 6.2 상태와 동작

| 상태 | 의미 | 가능한 동작 |
|------|------|-------------|
| **DRAFT** | 생성됨, 미발송 | **실시**(발송) · 취소 · 삭제 |
| **RUNNING** | 발송 완료, 추적 중 | **완료** · 취소 |
| **COMPLETED** | 훈련 종료 | 삭제 |
| **CANCELLED** | 취소됨 | 삭제 |

- **실시**: 확인 후 선택된 대상자 전원에게 메일을 **동기 발송**하고, 대상자별로 성공/실패를 기록합니다. 상태가 **RUNNING**으로 바뀝니다. (DRAFT 상태에서만 실시 가능)
- **완료**: 추적을 마감하고 상태를 **COMPLETED**로 바꿉니다. (RUNNING 상태에서만)
- **취소**: 상태를 **CANCELLED**로 바꿉니다.
- **삭제**: RUNNING 상태에서는 삭제할 수 없습니다(먼저 완료/취소).

> 발송은 대상자별로 개별 처리되며, 실패한 대상자는 실패 사유와 함께 기록됩니다(다음 절 참고). 발송 실패가 많다면 [2.1 SMTP 설정](#21-발송-메일서버smtp-설정)의 테스트를 먼저 확인하세요.

## 7. 열람·클릭 추적 원리

### 7.1 발송 시점

캠페인 실시 시, 각 대상자의 고유 토큰으로 본문 변수를 치환한 뒤 SMTP로 발송합니다.

- `{OPEN_URL}` → `{도메인}/api/phishing/track/{토큰}/open`
- `{CLICK_URL}` → `{도메인}/api/phishing/track/{토큰}/click`
- `{TARGET_NAME}` / `{TARGET_EMAIL}` → 대상자 이름·이메일

### 7.2 열람(open) 수집

수신자가 메일을 열면 본문 끝의 **1×1 투명 이미지**(추적 픽셀)가 로드되면서 `GET /api/phishing/track/{토큰}/open` 요청이 발생합니다. 서버는 토큰으로 대상자를 찾아 **`opened_at`을 최초 1회 기록**하고 1×1 GIF를 응답합니다. (인증이 필요 없는 공개 엔드포인트)

### 7.3 클릭(click) 수집

수신자가 본문 버튼/링크를 클릭하면 `GET /api/phishing/track/{토큰}/click` 요청이 발생합니다. 서버는 **`clicked_at`(및 `opened_at`이 비어 있으면 함께)을 기록**한 뒤, **피싱 인식 안내 페이지(`/phishing-awareness.html`)로 리다이렉트**합니다. 즉 클릭한 임직원은 곧바로 "방금 피싱 메일에 속았다"는 학습 안내를 보게 됩니다.

### 7.4 저장

열람·클릭 시각은 `phishing_campaign_targets` 테이블의 `opened_at` / `clicked_at` 컬럼에 대상자별로 저장됩니다. `opened_at`·`clicked_at`은 **각각 최초 1회만** 기록됩니다(재열람·재클릭 무시).

| **모의훈련 현황** 탭 | 캠페인별 발송/열람/클릭 요약, 상태 |
| 캠페인 **상세** | 대상자별 발송 성공/실패, 열람(●)·클릭(⚠)·신고(✓) 및 시각, 열람/클릭/신고 **집계** |
| **발송 로그** 탭 | 대상자별 발송 결과(성공 ✓ / 실패 ✕ + 실패 사유), 열람·클릭 |
| **교육 및 훈련 › 교육·훈련 결과 › 모의 훈련** 탭 | 캠페인별 열람률·클릭률·신고률, 평균 지표 |

- **클릭률**이 가장 신뢰할 수 있는 핵심 지표입니다. 클릭한 임직원은 추가 교육 대상으로 관리하는 것을 권장합니다.
- 발송 실패 대상자는 훈련 결과 집계를 왜곡할 수 있으므로, 실시 직후 **발송 로그**에서 실패 여부를 먼저 확인하세요.

## 9. 한계와 유의사항

1. **추적 도메인이 외부에서 접속 가능해야 합니다.** `app.base_url`이 `localhost`이거나 수신자가 접근할 수 없는 주소면 열람·클릭이 기록되지 않습니다.
2. **열람(open) 추적은 신뢰도가 낮습니다.** 대부분의 메일 클라이언트가 기본적으로 원격 이미지를 차단합니다.
   - 실제로 열어도 이미지 미로드로 `opened_at`이 안 찍힐 수 있습니다.
   - 반대로 **Gmail 이미지 프록시**가 픽셀을 선행 로드해, 열지 않았는데 열람으로 잡히는 오탐이 생길 수 있습니다.
   - → **클릭(click)이 훨씬 정확한 지표**입니다.
3. **신고(reported_at) 기능은 미구현 상태입니다.** 화면·집계 항목(신고률)은 있으나 이를 기록하는 경로가 없어 **현재 항상 0/미기록**입니다. "의심 메일 신고" 수집이 필요하면 별도 구현이 필요합니다.
4. **개인정보 취급 주의.** 발송대상의 이름·이메일과 반응 이력은 개인정보입니다. 목록은 마스킹되어 표시되며, 훈련 결과는 개인 징계가 아닌 **교육 목적**으로 활용하는 것을 권장합니다.
5. 발송은 실시 시점에 **동기(순차) 처리**되므로, 대상자가 매우 많으면 실시 처리에 시간이 걸릴 수 있습니다.

## 10. 문제 해결 (FAQ)

**Q. 발송 시 `Authentication failed` 오류가 납니다.**
A. SMTP 인증정보 문제입니다. [2.1](#21-발송-메일서버smtp-설정)에서 실제 계정으로 설정하고 **"이 설정 사용"을 체크**한 뒤 저장·테스트하세요. Gmail이면 **앱 비밀번호(16자리)** + **587 포트**를 사용해야 합니다.

**Q. 메일은 갔는데 열람이 하나도 안 잡힙니다.**
A. 정상일 수 있습니다. 메일 클라이언트의 이미지 차단 때문입니다([9-2](#9-한계와-유의사항)). 클릭률로 판단하세요. 클릭도 전혀 안 잡히면 `app.base_url`([2.2](#22-이메일-발송-링크-도메인-주소))이 수신자가 접속 가능한 외부 주소인지 확인하세요.

**Q. 클릭 링크를 눌러도 아무 일도 안 일어납니다 / 접속이 안 됩니다.**
A. 추적 도메인이 잘못되었을 가능성이 높습니다. `app.base_url`을 실제 서비스 도메인(HTTPS 권장)으로 설정하세요. `localhost`는 수신자 PC에서 접속되지 않습니다.

**Q. 캠페인을 삭제할 수 없습니다.**
A. **RUNNING** 상태에서는 삭제할 수 없습니다. 먼저 **완료** 또는 **취소** 처리 후 삭제하세요.

**Q. 신고율이 항상 0입니다.**
A. 신고 수집 기능이 아직 구현되지 않았습니다([9-3](#9-한계와-유의사항)).

**Q. 제목에 이름을 넣었는데 `{TARGET_NAME}` 그대로 나갑니다.**
A. 치환은 **본문에서만** 됩니다([4.2](#42-치환-변수)). 제목·발신자에는 변수를 사용하지 마세요.

## 11. 부록: API·권한·DB 참조

### 11.1 REST API

기준 경로: `/api/phishing`

| 메서드 | 경로 | 설명 | 권한 |
|--------|------|------|------|
| GET | `/templates` | 템플릿 목록 | 인증 |
| POST | `/templates` | 템플릿 생성 | ADMIN·MANAGER |
| PATCH | `/templates/{id}` | 템플릿 수정 | ADMIN·MANAGER |
| DELETE | `/templates/{id}` | 템플릿 삭제 | ADMIN |
| GET | `/targets` | 대상자 목록 | 인증 |
| POST | `/targets` | 대상자 생성 | ADMIN·MANAGER |
| PATCH | `/targets/{id}` | 대상자 수정 | ADMIN·MANAGER |
| PATCH | `/targets/{id}/toggle` | 활성/비활성 토글 | ADMIN·MANAGER |
| DELETE | `/targets/{id}` | 대상자 삭제 | ADMIN |
| GET | `/campaigns` | 캠페인 목록 | 인증 |
| GET | `/campaigns/{id}` | 캠페인 상세(대상자 결과 포함) | 인증 |
| POST | `/campaigns` | 캠페인 생성 | ADMIN·MANAGER |
| POST | `/campaigns/{id}/launch` | 실시(발송) | ADMIN·MANAGER |
| POST | `/campaigns/{id}/complete` | 완료 | ADMIN·MANAGER |
| POST | `/campaigns/{id}/cancel` | 취소 | ADMIN·MANAGER |
| DELETE | `/campaigns/{id}` | 삭제 | ADMIN |
| GET | `/send-logs` | 발송 로그 | 인증 |
| GET | `/track/{token}/open` | 열람 추적(픽셀) | **공개** |
| GET | `/track/{token}/click` | 클릭 추적(리다이렉트) | **공개** |

> `track/*` 엔드포인트는 수신자가 인증 없이 접근해야 하므로 공개(무인증)입니다. 대상자 식별은 추측이 어려운 고유 토큰으로만 이루어집니다.
