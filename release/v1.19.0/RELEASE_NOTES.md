# v1.19.0 릴리즈 노트

**릴리즈 일자**: 2026-07-25

**운영현황관리** 메뉴를 신설했습니다.
ISMS-P 심사에서 제출하는 *정보보호 관리체계 운영현황표* 서식을 화면으로 옮겨,
연간 어떤 보안 활동을 언제 수행하기로 했고 실제로 수행했는지를 **연도별로 구성·관리**합니다.

## 신규 기능

### 운영현황관리 (보안 운영 > 운영현황관리)

상단 탭으로 두 관리체계를 전환하며, 각각 별도의 항목 구성과 이행 실적을 갖습니다.

| 탭 | 표 구성 |
|----|---------|
| **정보보호 관리체계** | 구분 · 점검 기준 · 주기·시점 · 보안적용 실적(산출물) · 책임자 · 실무자 · 1~12월 |
| **개인정보보호 관리체계** | 점검항목 · 점검주기 · 상세 내용 · 1~12월 |

정보보호 관리체계는 **정책관리 · 자산관리 · 접근통제 · 암호화 관리 · 물리적 보안 · 인적보안 · 사고대응 · 기타** 8개 구분으로 묶이며, 같은 구분이 이어지는 행에서는 구분명을 한 번만 표시해 원본 서식의 병합셀과 같은 모양이 됩니다.

#### 연도별 구성

- 우측 상단 **← 2026년 →** 로 연도를 이동하며, 연도마다 항목 구성과 이행 실적이 따로 보관됩니다.
- **기본 항목 불러오기** — 표준 점검 항목(정보보호 **45개** / 개인정보보호 **10개**)을 월별 계획과 함께 등록합니다.
- **전년도 구성 복사** — 직전 연도의 항목과 월별 계획을 그대로 가져오고 **이행 실적은 초기화**합니다(연초 구성용).
- 두 기능 모두 해당 연도·구분에 항목이 있으면 **중복 생성되지 않고 안내 메시지**를 띄웁니다. 다시 구성하려면 **이 구분 전체 삭제**로 비운 뒤 실행합니다.
- **항목 추가·수정**으로 조직 상황에 맞게 점검 항목, 주기, 산출물, 담당자, 월별 계획을 직접 관리할 수 있습니다(구분·주기는 기존 값 자동완성 제공).

#### 월별 계획 / 이행 매트릭스

표의 1~12월 칸을 클릭하면 이행 여부가 바로 바뀝니다.

| 표시 | 의미 |
|------|------|
| **○** (회색) | 계획된 달 — 미이행 |
| **●** (녹색) | 계획된 달 — 이행 완료 |
| **▲** (주황) | 계획에 없었지만 수행함 (계획 외 수행) |
| (빈칸) | 계획 없음 |

- 계획(○)은 항목 수정의 *월별 계획*에서 지정하며 **매월 / 전체 해제** 버튼을 제공합니다.
- *상시*·*수시* 항목처럼 특정 월 계획이 없는 경우 계획을 비워 두고 수행한 달에만 이행 표시를 하면 ▲로 기록됩니다.
- 행 끝의 **이행** 열은 `이행/계획` 건수이며 계획을 모두 채우면 녹색으로 바뀝니다.

#### 요약

- **이행률** = 이행 완료 칸 ÷ 계획된 칸 (90%↑ 녹색 / 70%↑ 노랑 / 미만 빨강)
- **점검 항목** 수 · **미이행** 칸 수 · **계획 외 수행** 칸 수
- **월별 계획 대비 이행** 막대 — 막대 높이는 그 달의 계획 건수, 채워진 부분은 이행 건수

## 권한

- 조회는 로그인한 사용자, **등록·수정·삭제·이행 표시는 MANAGER 이상**입니다.
- RBAC 메뉴 키 **`operation_status`** 가 추가되었습니다(총 43개). 권한관리 > 기본 역할 권한과 커스텀 Role에서 메뉴별로 제어할 수 있습니다.
- 항목 등록·수정·삭제와 연도 구성(기본 항목 불러오기·복사·전체 삭제)은 **감사로그**에 기록됩니다.

## API 변경

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `GET` | `/api/operation-status/years` | 등록된 연도 목록 |
| `GET` | `/api/operation-status?year=&type=` | 항목 목록 (type = ISMS \| PRIVACY) |
| `GET` | `/api/operation-status/summary?year=` | 연도 이행 집계 (유형별·월별) |
| `POST` | `/api/operation-status` | 항목 등록 (MANAGER+) |
| `PATCH` | `/api/operation-status/{id}` | 항목 수정 (MANAGER+) |
| `PATCH` | `/api/operation-status/{id}/month` | 월 칸 계획/이행 토글 (MANAGER+) |
| `DELETE` | `/api/operation-status/{id}` | 항목 삭제 (MANAGER+) |
| `POST` | `/api/operation-status/defaults?year=&type=` | 기본 항목 불러오기 (MANAGER+) |
| `POST` | `/api/operation-status/copy?fromYear=&toYear=&type=` | 연도 구성 복사 (MANAGER+) |
| `DELETE` | `/api/operation-status?year=&type=` | 연도·구분 전체 삭제 (MANAGER+) |

## 데이터베이스

- 신규 테이블 **`operation_status_items`** — **ddl-auto 로 자동 생성**되므로 별도 마이그레이션이 필요 없습니다.
- 월별 계획·이행은 컬럼 24개 대신 **12비트 마스크**(`plan_months` / `done_months`, bit 0 = 1월)로 저장하고, API 응답에서는 `boolean[12]` 로 변환해 전달합니다.
- 기본 항목은 마스터 테이블이 아닌 코드 상수(`OperationStatusDefaults`)로 두고 **연도별로 복제**합니다. 참고 서식에서 생성하는 스크립트 `scripts/gen_opstatus_defaults.py` 를 함께 제공하므로, 서식이 바뀌면 스크립트를 다시 실행해 갱신합니다.
