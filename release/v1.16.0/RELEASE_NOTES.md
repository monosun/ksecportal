# v1.16.0 릴리즈 노트

**릴리즈 일자**: 2026-07-24

ISMS-P 증적관리에 **전년도 증적 가져오기 / 가져오기 초기화**를 추가하고, ISMS-P 101항목의 **기본 증적·이행가이드**를 코드관리에서 다루도록 정비했습니다. 함께 **모바일 화면 대응**, 취약점 **댓글 수정·삭제**, 자산 목록 **자산유형 필터**를 반영했습니다.

## 신규 기능

### ISMS-P 증적관리 — 전년도 증적 가져오기

연도 이동 버튼 옆의 **전년도 증적 가져오기** 버튼으로, 이전 연도에 등록한 증적을 조회 중인 연도로 한 번에 복사합니다.

1. 복사받을 연도(예: 2026)를 선택하고 **전년도 증적 가져오기** 클릭
2. 확인 팝업에서 원본 연도(증적이 있는 **가장 최근** 연도)를 확인하고 **가져오기**
3. 결과(증적 건수 · 현재상태/의견 건수 · 건너뛴 항목 수)가 목록 위에 표시

- 복사 대상: **증적제목 · 증적내용 · 준수상태 · 첨부파일** + 연도별 **현재 상태 · 의견**
- 첨부파일은 **실물을 복제**하므로 한쪽 연도의 증적을 삭제해도 다른 연도가 깨지지 않습니다.
- 대상 연도에 **이미 증적이 있는 항목은 건너뜁니다** — 여러 번 눌러도 중복 복사되지 않습니다.
- 다른 항목을 참조(🔗)하는 증적은 원본 참조를 그대로 이어받습니다.
- 가져올 이전 연도 증적이 없으면 버튼이 비활성화됩니다.

### ISMS-P 증적관리 — 가져오기 초기화

**전년도 증적 가져오기** 옆의 **가져오기 초기화** 버튼으로 가져오기 전 상태로 되돌립니다.

- 가져오기로 생성된 증적·현재상태·의견만 삭제합니다. **직접 등록·작성한 기록은 삭제되지 않습니다.**
- 원본 연도의 증적과 첨부파일은 그대로 유지됩니다.
- 가져온 뒤 수정한 내용도 함께 삭제되므로, 확인 팝업에 삭제 대상 건수(증적/의견, 원본 연도)를 먼저 보여줍니다.
- 가져온 증적을 다른 항목에서 참조 중이면 해당 참조 증적도 함께 삭제되고 결과에 건수가 표시됩니다.
- 되돌릴 내역이 없으면 버튼이 비활성화됩니다.

### 코드관리 — ISMS-P 101항목 탭

**관리 > 코드관리**에 **ISMS-P 101항목** 탭을 추가해 항목별 **기본 증적제목 · 기본 증적내용 · 이행가이드**를 편집할 수 있습니다.

- 항목코드·항목명·증적제목 키워드 검색 지원
- 여기서 관리한 기본값이 **증적 일괄등록 엑셀 템플릿**의 기본값으로 사용됩니다.
- 일괄등록 템플릿이 **항목별 한 행씩 미리 채워진 형태**로 바뀌었고 **이행가이드** 열이 추가되었습니다(선택 입력 — 값을 채워 올리면 해당 항목의 가이드가 갱신됩니다). 증적제목·증적내용·파일명·준수상태가 모두 빈 행은 미작성으로 보고 건너뜁니다.
- 101개 항목의 **이행가이드·기본 증적제목·기본 증적내용 기본 문안을 시드**했습니다. 기존 설치본은 기동 시 **비어 있는 값만 백필**되며 이미 입력한 값은 덮어쓰지 않습니다.

### 취약점 — 댓글 수정·삭제

취약점 상세의 댓글을 **작성자 본인**이 수정·삭제할 수 있습니다. 수정된 댓글은 수정 시각이 함께 표시되며, 삭제는 감사로그(`VULN_COMMENT_DELETED`)에 기록됩니다.

### 자산관리 — 자산유형 필터

자산 목록에 **자산유형(정보/소프트웨어/하드웨어/서비스/인력/시설) 필터와 컬럼**을 추가했습니다(서버 측 조회 조건). 필터를 바꾸면 첫 페이지로 이동합니다. 서비스 자산 조회도 클라이언트 필터링 대신 서버 조건을 사용하도록 정리했습니다.

## 개선

### 모바일 화면 대응

- 좌측 사이드바를 모바일에서 **오버레이 방식**으로 열고 닫도록 변경
- 페이지 헤더·본문 여백을 화면 크기에 따라 축소(`page-header`, `page-body`)
- 목록 **테이블 25종 이상을 가로 스크롤 컨테이너**로 감싸 좁은 화면에서 페이지 전체가 흔들리지 않도록 수정

## 데이터베이스 · API

- `isms_evidences.copied_from_year`, `isms_item_notes.copied_from_year` 컬럼 신규 — 가져오기로 생성된 레코드 식별용(직접 등록은 `null`). **nullable 컬럼이라 `ddl-auto: update`로 자동 반영**되며 별도 마이그레이션이 필요 없습니다. 신규 설치 스키마(`db/init/06_isms.sql`)에도 반영했습니다.
- `isms_items.default_evidence_title`, `isms_items.default_evidence_content` 컬럼 신규 (동일하게 자동 반영)
- `vulnerability_comments.updated_at` 컬럼 신규 (미수정 댓글은 `null`)

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `GET` | `/api/isms/copy-previous/status` | 가져올 수 있는 이전 연도, 되돌릴 수 있는 건수 |
| `POST` | `/api/isms/copy-previous` | 전년도 증적·현재상태·의견 복사 (MANAGER+) |
| `DELETE` | `/api/isms/copy-previous` | 가져오기 초기화 (MANAGER+) |
| `PATCH` | `/api/isms/items/{id}/defaults` | 항목 기본 증적제목·증적내용·이행가이드 저장 (MANAGER+) |
| `PATCH` | `/api/vulnerabilities/{id}/comments/{commentId}` | 댓글 수정 (작성자 본인) |
| `DELETE` | `/api/vulnerabilities/{id}/comments/{commentId}` | 댓글 삭제 (작성자 본인) |

- `GET /api/assets`에 `assetCategory` 필터 파라미터 추가

## 내부 구조

- `IsmsService.copyFromPreviousYear()` / `revertCopyPrevious()` / `copyPreviousStatus()` 신규. 복사 시 `copiedFromYear`에 원본 연도를 남겨 초기화가 **가져온 레코드만 정확히** 지웁니다.
- `FileStorageService.copy(relativePath, subDir)` 신규 — 저장된 파일을 새 경로로 복제(원본 없으면 `null` 반환). 경로만 공유하면 한쪽 삭제 시 다른 연도 파일까지 지워지므로 실물을 복제합니다.
- `IsmsDataInitializer`가 기존 항목의 빈 가이드·기본 증적값을 시드에서 **백필**하도록 확장(seed-when-empty 유지, 사용자 입력값은 보존).

## 업그레이드

```bash
docker compose build backend frontend
docker compose up -d backend frontend
```

DB 마이그레이션은 필요 없습니다(신규 컬럼은 모두 nullable — 기동 시 자동 추가). 배포 후 브라우저 하드 리프레시(Ctrl+Shift+R)를 권장합니다.
