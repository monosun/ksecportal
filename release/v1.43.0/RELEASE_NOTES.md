# KSecPortal v1.43.0 릴리즈 노트

**릴리즈 일자**: 2026-11-06

**정보보호 관리체계 > 보안정책관리**를 새로 만들어, 규정·지침·가이드·절차서·매뉴얼 등 정보보호 정책 문서를
**문서별로 버전(제·개정본)과 개정사항을 파일 단위로** 관리하고, 첨부한 문서를 **뷰어로 바로 열람**할 수 있게 했습니다.
본문을 조문 단위로 작성·매핑하는 기존 **보안 정책** 메뉴와 달리, 승인된 정책 문서 원본과 제·개정 이력(ISMS-P 2.1.1 정책의 유지관리 증적)에 초점을 둔 문서 대장입니다.

---

## 1. 보안정책관리 (신규)

메뉴 위치: **정보보호 관리체계 > 보안 정책** 바로 아래.

### 분류

| 분류 | 예시 |
|------|------|
| 규정 | 정보보호 규정, 개인정보보호 규정 |
| 지침 | 접근통제 지침, 암호화 지침 |
| 가이드 | 안전한 비밀번호 가이드 |
| 절차서 | 침해사고 대응 절차서 |
| 매뉴얼 | 보안솔루션 운영 매뉴얼 |

- 상단 **분류 탭**(전체 + 5개 분류, 탭마다 문서 수 표시), **상태 필터**(시행/폐지), 검색(문서명·문서번호·주관부서·담당자·설명).
- 목록에 분류·문서번호·문서명·현행 버전(구분 배지, 버전 수)·제·개정일·시행일·주관부서·상태·**보기** 버튼.

### 문서·버전 관리

- **문서 기본정보**: 분류·문서명(필수), 문서번호, 주관부서, 관리 담당자, 설명.
- **관리 담당자·승인자는 등록된 사용자에서 선택**(이름·부서 표시)하고, 사용자로 등록되지 않은 사람은 **직접 입력**할 수 있습니다. 주관부서는 코드관리 부서 목록에서 선택 또는 직접 입력.
- **버전 1건 = 파일 1개 + 개정사항**: 버전 번호, 구분(**제정 / 개정 / 폐지**), 제·개정일, 시행일, 승인자, 제·개정·폐지 사유, 주요 개정사항.
- 상세 팝업의 **버전 이력**은 최신순 타임라인이며, 맨 위가 `현행` 버전입니다(제·개정일 기준이라 과거 개정본을 뒤늦게 올려도 순서가 맞음).
- 새 버전 등록 시 버전 번호를 비우면 **자동 증가**(1.1 → 1.2), 같은 문서의 **중복 버전 번호는 거부**.
- 버전 정보 수정, **파일 교체**(잘못 올린 파일 정정), 버전 삭제(마지막 1개는 삭제 불가 — 문서 삭제 사용).
- 현행 버전이 **폐지**이면 문서 상태가 자동으로 **폐지**, 폐지 버전을 삭제하면 다시 **시행**.
- 첨부 형식: PDF·DOC(X)·ODT·RTF·PPT(X)·XLS(X)·TXT·HWP(X), 최대 100MB.

### 뷰어

- 목록 **보기**, 상세 **현행본 보기**, 버전별 **보기**로 내려받지 않고 화면에서 바로 확인합니다.
- PDF·엑셀·텍스트는 바로, **DOC·DOCX·PPT·PPTX** 는 서버(Gotenberg)가 PDF 로 변환해 표시(첫 변환 후 캐시).
- **HWP·HWPX 는 변환 미지원**이라 다운로드로 확인합니다. 임직원 열람용으로는 PDF 등록을 권장합니다.

### 권한

- RBAC 메뉴 키 **`policy_management`** 신설(권한관리 화면의 **보안정책관리**). 조회·쓰기·삭제를 **서버(`@menuAuth`)에서도 검사**합니다.
- **ADMIN** 전체, **MANAGER** 기본 역할에는 기동 시 자동 추가(조회·등록·수정·삭제).
- **USER** 는 **신규 설치 시 조회 권한**이 기본 부여됩니다(정책 공표용). **기존 설치는 관리 > 권한관리에서 USER 역할에 보안정책관리 읽기를 직접 켜야** 임직원이 볼 수 있습니다.
- 모든 등록·개정·수정·파일 교체·삭제는 감사로그(`POLICY_DOC_*`)에 기록됩니다.

## 2. 개선

- **신규 메뉴 배치 개선** — 관리 > 메뉴순서에서 순서를 저장해 둔 환경에서는 새로 추가된 메뉴가 그룹 **맨 아래**로 가던 문제를, 기본 정의상 **바로 앞 메뉴 다음**에 끼워 넣도록 바꿨습니다(이번 보안정책관리도 보안 정책 바로 아래 표시).

## 3. DB 변경

- 신규 테이블 `policy_mgmt_docs`, `policy_mgmt_revisions` — 운영 중인 DB 는 기동 시 자동 생성(`ddl-auto: update`)되므로 **별도 마이그레이션 불필요**. 신규 설치 스키마는 `db/init/14_policy_mgmt.sql`.

## 4. 업그레이드

```bash
git pull
docker compose build backend frontend
docker compose up -d backend frontend
```

배포 후 브라우저 강력 새로고침(Ctrl+Shift+R). 임직원에게 정책 문서를 공개하려면 **관리 > 권한관리 > USER** 에서 보안정책관리 **읽기**를 켜 주세요.

## API

`/api/policy-docs` — 목록·분류별 건수·상세·등록·수정·삭제, `/{id}/revisions` 버전 등록, `/revisions/{id}` 수정·삭제·파일 교체·다운로드·미리보기(PDF 변환). 상세는 `docs/api.md` 참고.
