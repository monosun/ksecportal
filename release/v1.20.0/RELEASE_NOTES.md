# v1.20.0 릴리즈 노트

**릴리즈 일자**: 2026-07-25

운영현황관리의 **기본 항목을 코드 관리에서 직접 관리**하도록 바꾸고,
운영현황관리에서 항목을 추가할 때 **그 기본항목을 골라 쓰거나 직접 입력**할 수 있게 했습니다.

v1.19.0 에서는 기본 항목이 코드 상수로 고정되어 있어 조직에 맞게 바꾸려면 코드 수정이 필요했습니다.

## 신규 기능

### 관리 > 코드 관리 > 운영현황 기본항목

코드 관리에 **운영현황 기본항목** 탭이 추가되었습니다(총 8개 탭).

- 탭 안에서 **정보보호 관리체계 / 개인정보보호 관리체계**를 전환하며, 각각 별도 목록으로 관리합니다.
- 항목별로 **구분 · 점검 기준(점검항목) · 주기 및 시점 · 보안적용 실적(상세 내용) · 책임자 · 실무자 · 월별 기본 계획 · 정렬 순서 · 사용 여부**를 등록·수정·삭제합니다.
- **월별 기본 계획**은 연도별 운영현황에 불러올 때 적용되는 초기 계획입니다(매월 / 전체 해제 버튼 제공). 상시·수시 항목은 모두 해제해 둡니다.
- 구분·점검항목·주기·산출물 통합 검색과 20건 페이지네이션을 제공합니다.
- 최초 기동 시 표준 항목(**정보보호 45개 / 개인정보보호 10개**)이 자동 등록됩니다.

> **삭제보다 미사용을 권장합니다.** 특정 구분의 기본 항목을 **모두 삭제하면 다음 기동 시 표준 항목이 다시 생성**됩니다(신규 설치·구 볼륨·DB 재생성 대비 자동 복구 시더). 쓰지 않는 항목은 **사용** 체크를 해제하면 목록·불러오기·선택 목록에서 제외됩니다. 삭제 확인 창에도 같은 안내가 표시됩니다.

### 운영현황관리 — 항목 추가 시 기본항목 선택

**보안 운영 > 운영현황관리 > 항목 추가**에서 점검 기준을 고르는 방식이 바뀌었습니다.

- 점검 기준(점검항목)이 **기본항목 선택 드롭다운**으로 바뀌었고, 정보보호 관리체계는 **구분별로 묶여**(optgroup) 표시됩니다.
- 항목을 선택하면 **주기 · 산출물 · 책임자 · 실무자 · 월별 계획이 함께 채워집니다.** 채워진 값은 이후 자유롭게 수정할 수 있습니다.
- 목록에 없는 항목은 **`＋ 목록에 없음 — 직접 입력`** 을 선택해 직접 입력합니다. 직접 입력 상태에서 **목록에서 선택**으로 되돌아갈 수 있습니다.
- 기본항목이 하나도 없거나 조회에 실패하면 **자동으로 직접 입력 모드**로 열립니다(등록이 막히지 않도록).
- 기존 항목 **수정** 시에는 이름이 이미 정해져 있으므로 항상 직접 입력 상태로 열립니다.

### 기본 항목 불러오기 — 코드 관리 목록 기준

**기본 항목 불러오기**가 코드 상수가 아니라 **코드 관리에 등록된 사용 중인 기본항목**을 해당 연도로 복제합니다.
코드 관리에서 항목을 추가·수정하면 이후 불러오는 연도에 그대로 반영됩니다.
해당 구분의 기본항목이 하나도 없으면 "코드 관리에서 먼저 등록하세요" 안내를 표시합니다.

## API 변경

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `GET` | `/api/operation-status/default-items?type=&activeOnly=` | 기본항목 마스터 목록 (MANAGER+ — 운영현황 선택 목록으로 사용) |
| `POST` | `/api/operation-status/default-items` | 기본항목 등록 (ADMIN) |
| `PATCH` | `/api/operation-status/default-items/{id}` | 기본항목 수정 (ADMIN) |
| `DELETE` | `/api/operation-status/default-items/{id}` | 기본항목 삭제 (ADMIN) |

- `POST /api/operation-status/defaults` 의 동작이 바뀌었습니다 — 코드 상수 대신 **기본항목 마스터(active=true)** 를 복제합니다.
- 기본항목 등록·수정·삭제는 **감사로그**(`OPERATION_STATUS_DEFAULT`)에 기록됩니다.

## 데이터베이스

- 신규 테이블 **`operation_status_defaults`** — **ddl-auto 로 자동 생성**되므로 별도 마이그레이션이 필요 없습니다.
- `OperationStatusDefaultInitializer`(seed-when-empty)가 **구분별로 비어 있을 때만** 표준 항목을 시드합니다. 이미 있으면 건너뛰므로 관리자가 수정한 내용은 재기동해도 보존됩니다.
- 참고 서식에서 코드 상수를 만드는 `scripts/gen_opstatus_defaults.py` 는 그대로 유지됩니다 — 이제 그 상수는 **최초 시드 값**의 역할만 합니다.

## 업그레이드

```bash
git pull
docker compose build backend frontend
docker compose up -d backend frontend
```

브라우저 하드 리프레시(Ctrl+Shift+R) 후 **관리 > 코드 관리 > 운영현황 기본항목** 탭에서 기본 항목이 채워졌는지 확인하십시오. 기동 로그에서도 확인할 수 있습니다.

```
[운영현황] ISMS 기본 항목 45건 초기화
[운영현황] PRIVACY 기본 항목 10건 초기화
```

기존에 v1.19.0 으로 이미 구성한 연도 데이터는 영향을 받지 않습니다.
