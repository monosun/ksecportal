# v1.18.0 릴리즈 노트

**릴리즈 일자**: 2026-07-25

대시보드 **ISMS-P 이행률**을 스크롤 없이 한 화면에서 보도록 재구성하고,
**권한관리**에서 기본 역할(ADMIN·MANAGER·USER)의 현재 권한을 확인하고 수정할 수 있게 했습니다.
문서 전반의 제품명을 **KSecPortal** 로 통일했습니다.

## 신규 기능

### 대시보드 — ISMS-P 이행률 한 화면 재구성

21개 도메인이 세로로 길게 흐르고 같은 수치가 카드 두 곳에 반복되던 화면을, **요약 1줄 + 도메인 3열** 구조로 다시 만들었습니다.

- **상단 요약** — 전체 이행률 게이지, 상태 구성 막대, 상태별 건수(준수 · 부분 준수 · 미준수 · 증적 미제출 · 해당없음)를 한 줄에 배치했습니다. 기존 `전체 이행률` 카드와 `통제항목 현황` 카드가 같은 숫자를 두 번 보여주던 것을 하나로 합쳤습니다.
- **도메인별 이행률** — 21개 도메인을 인증기준 **3개 섹션**(1. 관리체계 수립 및 운영 / 2. 보호대책 요구사항 / 3. 개인정보 처리단계별 요구사항)으로 나눠 3열로 배치하고, 각 줄을 `도메인 코드 · 이름 · 준수/평가대상 · 이행률 + 진행 막대` 2줄로 압축했습니다. 섹션 제목 옆에 섹션 전체 이행률이 표시됩니다.
- **이행률 계산 기준 명시** — `준수 ÷ (전체 − 해당없음)`. 해당없음(NA) 항목은 분모에서 빠지며, 평가 대상이 전혀 없는 도메인은 `—` 로 표시합니다(0% 로 오인되지 않도록).
- **도메인 클릭 시 이동** — 해당 도메인이 선택된 상태로 **ISMS-P 증적관리**가 열립니다(`/isms?domain=<코드>`).
- 색상 기준(80%↑ 녹색 / 60%↑ 노랑 / 미만 빨강)과 색 토큰을 개인정보 현황보고서와 동일하게 맞췄습니다. 상단에 **새로고침** 버튼을 추가했습니다.

### 권한관리 — 기본 역할(ADMIN·MANAGER·USER) 권한 표시·수정

지금까지 권한관리 화면에는 관리자가 만든 **커스텀 Role만** 보였고, 계정 역할 자체의 권한은 화면에서 확인할 수 없었습니다.
이제 **관리 > 권한관리** 상단에 기본 역할 카드 3개가 표시되고, MANAGER·USER는 권한을 직접 수정할 수 있습니다.

| 역할 | 초기 권한 | 수정 |
|------|-----------|------|
| **ADMIN** | 전체 메뉴 읽기·쓰기·삭제 | 불가 (항상 전체 권한) |
| **MANAGER** | 전체 메뉴 읽기·쓰기·삭제 | 가능 |
| **USER** | IT 및 정보보호 교육 · 보안 가이드 및 자료 읽기 | 가능 |

- 카드에 **계정 수**, 허용 메뉴 수, 쓰기·삭제 허용 건수와 메뉴 목록(R·W·D)이 표시됩니다. 전 메뉴가 모두 허용이면 "전체 메뉴 읽기·쓰기·삭제" 한 줄로 요약합니다.
- **수정**을 누르면 커스텀 Role과 같은 메뉴별 권한 표가 열리며, **전체 선택 / 전체 해제** 버튼이 추가되었습니다.
- 최종 권한은 **기본 역할 권한 ∪ 배정된 커스텀 Role 권한**(OR 합산)입니다.
- 모든 권한을 해제하면 해당 역할 계정의 메뉴가 사라지므로 저장 전 확인 창이 뜹니다.
- 기본 역할 행은 커스텀 Role 목록에 섞이지 않으며, 이름 변경·삭제·사용자 배정이 차단됩니다.

> **적용 범위** 기본 역할 권한은 **화면(메뉴·버튼) 노출**을 제어합니다. 서버 API는 이와 별개로 역할 기반 검사(`@PreAuthorize`)를 수행하므로, MANAGER의 쓰기를 해제해도 API 호출 자체가 차단되지는 않습니다. 화면과 API를 모두 제한하려면 계정 역할을 USER로 두고 필요한 Role만 배정하십시오.

- 설명 문서(.md) 16개에서 제품명 `SecPortal` → **`KSecPortal`** 로 통일했습니다(README·INSTALL·사용자 매뉴얼·Okta/Slack 연동·설치/배포 가이드 등 51곳).
- 자바 클래스명(`SecPortalApplication`), 패키지(`com.monosun.secportal`), 컨테이너명(`secportal-backend` 등), 기본 관리자 계정(`secportal@monosun.com`), DB 이름은 **변경하지 않았습니다**.

## 변경 사항

### 동작 변경 — MANAGER 메뉴 노출 방식

기존에는 프론트엔드가 MANAGER를 **무조건 전체 허용**으로 처리해 권한 설정과 무관하게 모든 메뉴를 보여줬습니다.
이제 MANAGER도 기본 역할 권한을 따릅니다.

- 최초 기동 시 `RbacBuiltinRoleInitializer` 가 MANAGER 기본 역할을 **전 메뉴 읽기·쓰기·삭제**로 시드하므로 **기존 계정의 화면은 그대로**입니다.
- USER 기본 역할도 기존 하드코딩 기본값(교육·보안 가이드 읽기)과 동일하게 시드됩니다. 기존 `DEFAULT_USER_PERMISSIONS` 상수는 제거되고 DB 값으로 대체되었습니다.
- 기본 역할 행이 없으면(초기화 실패·구 볼륨 등) 메뉴가 통째로 사라지지 않도록 **전체 허용으로 폴백**합니다(`MyPermissions.fullAccess`).

### 권한 설정 대상 메뉴 보강

권한관리 메뉴 목록에서 빠져 있던 **소스 취약점 점검(SAST)**, **모의 악성메일 훈련**을 추가했습니다(총 42개). 프론트 `navMenu.js` · 권한관리 화면 · 백엔드 `MenuKeys` 세 곳의 메뉴 키가 일치합니다.

## API 변경

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `GET` | `/api/admin/roles/builtin` | 기본 역할 3종의 현재 권한·계정 수 조회 (ADMIN) |
| `PUT` | `/api/admin/roles/builtin/{role}` | MANAGER·USER 권한 저장 (ADMIN, ADMIN 지정 시 오류) |

- `GET /api/auth/my-permissions` 응답에 `fullAccess` 필드가 추가되었습니다.
- `GET /api/admin/roles` 는 기본 역할 시스템 행을 제외한 커스텀 Role만 반환합니다.

## 데이터베이스

- `custom_roles.builtin_role VARCHAR(20) NULL` 컬럼 추가 — **ddl-auto 로 자동 반영**되므로 별도 마이그레이션이 필요 없습니다.
- 기동 시 `RbacBuiltinRoleInitializer`(seed-when-empty)가 MANAGER·USER 기본 역할 행과 권한을 생성합니다. 이미 있으면 건너뜁니다.

```
[RBAC] USER 기본 역할 권한 2개 메뉴로 초기화
```
