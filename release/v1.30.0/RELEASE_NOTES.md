# KSecPortal v1.30.0 릴리즈 노트

**릴리즈 일자**: 2026-08-06

재해복구·업무연속성(BCP) 훈련과 비상연락망을 신설해 **사고 대응 체계의 준비 → 훈련 → 평가 → 연락**을 포털 안에서 이어지도록 했습니다.

## 신규 기능

### 1. 재해복구·BCP 훈련 (교육 및 훈련 > 재해복구·BCP 훈련)

재해 상황을 가정한 시나리오로 DR·BCP 훈련을 실시하고 단계별 수행 결과로 대응 체계의 실효성을 평가합니다.

**훈련 시나리오**
- 재해 유형·난이도·대상 시스템·**목표 RTO/RPO**·상황 설정·훈련 목표
- **대응 단계** — 단계명, 담당 역할, 수행 절차, 목표 소요시간, 성공 판정 기준
- 실시 이력이 있는 시나리오는 삭제 대신 **비활성** 처리 (과거 훈련 기록 보존)

**기본 시나리오 예제 7종** — `BcpScenarioInitializer`(seed-when-empty)가 단계까지 포함해 시드

| 시나리오 | 재해 유형 | 목표 RTO/RPO | 단계 |
|----------|-----------|--------------|------|
| 주 데이터센터 정전으로 인한 전산 서비스 중단 | 시설·전원 | 4시간 / 1시간 | 6 |
| 랜섬웨어 감염 확산에 따른 핵심 서버 암호화 | 사이버공격 | 8시간 / 24시간 | 7 |
| 핵심 DB 서버 장애에 따른 DR 사이트 전환 | 시스템장애 | 2시간 / 15분 | 6 |
| 클라우드 리전 장애로 인한 서비스 중단 | 시스템장애 | 3시간 / 30분 | 6 |
| 사옥 화재로 인한 업무 공간 접근 불가 | 자연재해·시설 | 8시간 / 4시간 | 6 |
| 통신 회선 이중화 동시 장애 (ISP 장애) | 네트워크 | 1시간 / 0분 | 5 |
| 개인정보 대량 유출 사고 대응 | 사이버공격 | 4시간 / 0분 | 7 |

**훈련 진행 및 평가**
- 훈련 방식 — **도상훈련 / 시뮬레이션 / 실제 전환**
- 등록 시 시나리오 단계를 **훈련 시점 값으로 복사** — 이후 시나리오를 수정해도 진행 중·완료 훈련은 영향 없음
- 계획 → 진행중 → 완료 상태 전이, 단계별 **성공 / 부분 / 실패** + 실제 소요시간·특이사항 기록
- 완료 시 달성률 자동 산출(성공 1.0 · 부분 0.5 · 실패 0의 가중 평균)과 판정 부여 — **80% 이상 적합 · 60% 이상 보완필요 · 그 미만 부적합**
- 미기록(미수행) 단계가 남아 있으면 완료 처리 거부
- 목표 대비 **실제 RTO 달성 여부** 표시, 훈련 총평·도출된 개선사항 기록

### 2. 교육·훈련 결과에 BCP 훈련 결과 탭 추가

**교육 및 훈련 > 교육·훈련 결과**에 세 번째 탭 **재해복구·BCP 훈련 결과** 신설.
- 실시/완료/적합 건수, 평균 달성률, **목표 RTO 달성률** 요약 카드
- 훈련별 성공·부분·실패 누적 막대
- 훈련 실시 이력 표 (목표/실제 RTO 대비, 달성률, 판정, 상태)
- 훈련 총평 및 도출된 개선사항 모아보기

### 3. 비상연락망 (보안 운영 > 비상연락망)

침해사고·개인정보 유출·재해 상황에서 **누구에게 어떤 순서로 연락할지**를 관리합니다.

- **연락 그룹** — 내부 조직 / 외부 기관 / 협력사·유지보수 구분, 표시 순서
- **연락처** — 연락 순서(1차·2차…), 비상 시 역할, 부서·직위, 사무실/휴대전화/이메일, **24시간 연락 가능** 여부, 비고
- 이름·소속·역할·부서·직위 통합 검색, 구분 필터, 비활성 포함 토글
- 연락처가 남아 있는 그룹은 삭제 거부

**기본 연락 계통 6종 자동 시드** (`EmergencyContactInitializer`) — 침해사고 대응반 / 개인정보 유출 대응반 / 재해복구·시스템 장애 대응반 / 경영진 보고 계통 / 외부 신고·문의 기관 / 협력사·유지보수 업체.
내부 대응반은 조직마다 구성이 다르므로 **그룹 골격만** 만들고 담당자는 직접 등록합니다.

**외부 신고기관 연락처 4건** — 공개된 국가기관 대표 신고번호

| 기관 | 연락처 | 용도 |
|------|--------|------|
| KISA 인터넷침해대응센터 | 118 (24시간) | 해킹·악성코드·DDoS 등 침해사고 신고 |
| KISA 개인정보침해 신고상담센터 | 118 (24시간) | 개인정보 유출·오남용 신고 및 상담 |
| 경찰청 사이버범죄 신고상담 | 182 (24시간) | 해킹·전자금융사기 등 사이버범죄 신고 |
| 국가정보원 산업기밀보호센터 | 111 (24시간) | 산업기술·영업비밀 유출 신고 |

## 개인정보 보호 처리

비상연락망은 연락 목적상 **즉시 전화가 걸려야** 하므로, 항목별로 처리 수준을 나눴습니다.

| 항목 | 처리 |
|------|------|
| 휴대전화 · 이메일 | **저장 시 암호화**(AES-256-GCM, `EncryptedStringConverter`) + 목록 **마스킹** |
| 사무실 · 대표 전화 | 기관·부서 대표번호로 쓰이므로 평문 저장·원문 표시, `tel:` 링크로 즉시 연결 |
| 이름 · 소속 · 역할 | 연락망의 식별 기능이므로 원문 표시 |

감사 로그에는 그룹명·이름만 남기고 **연락처 값은 기록하지 않습니다.**

### 마스킹 해제 권한의 화면 단위 예외 (동작 변경)

기존에는 마스킹 해제가 **ADMIN 전용**이었습니다. 비상연락망은 사고 발생 시 대응 실무자가 즉시 연락해야 하므로 **MANAGER도 해제할 수 있도록** 예외를 두었습니다.

- `stores/piMasking.js` 에 `MANAGER_REVEALABLE_SCREENS`(현재 `비상연락망`) 도입 — 여기에 등록된 화면에서만 MANAGER 해제 허용
- **MANAGER의 해제는 해제한 화면에서만 유효** — 다른 메뉴로 이동하면 즉시 다시 마스킹
- **ADMIN의 기존 동작(해제가 전 화면 유지)은 변경 없음**
- 해제 시 감사 로그(`PI_UNMASK`, 화면명 포함) 기록은 종전과 동일
- `PiMaskToggle` 이 `screen` 을 스토어에 등록/해제(`setScreen`·`clearScreen`) — 화면 전환 시 마운트·언마운트 순서와 무관하게 안전

> 마스킹은 **화면 표시 통제**이며 접근 통제가 아닙니다. API 응답 자체는 읽기 권한이 있는 사용자에게 복호화된 값을 반환합니다(기존 설계 유지).

## 변경 사항 요약

### 백엔드
- 신규 도메인 `com.monosun.secportal.bcp` — 시나리오·단계·훈련·훈련단계 4개 엔티티, `/bcp/scenarios`·`/bcp/exercises`
- 신규 도메인 `com.monosun.secportal.emergency` — 연락 그룹·연락처 2개 엔티티, `/emergency-contacts/groups`·`/contacts`
- seed-when-empty 초기화기 2종 — `BcpScenarioInitializer`(`@Order(61)`), `EmergencyContactInitializer`(`@Order(62)`)
- RBAC 메뉴 키 추가 — `bcp_training`, `emergency_contacts` (기동 시 MANAGER 기본 역할에 자동 보충)
- 모든 변경은 `auditLogService` 기록. 조회는 인증 사용자, 쓰기는 MANAGER 이상, 삭제는 ADMIN(연락처 삭제는 MANAGER)

### 프론트엔드
- 신규 화면 `views/bcp/BcpTrainingView.vue`, `views/emergency/EmergencyContactView.vue`
- `views/training/TrainingResultsView.vue` — 재해복구·BCP 훈련 결과 탭 추가
- `api/index.js` — `bcpApi`, `emergencyContactApi` 추가
- `config/navMenu.js`·`router/index.js`·`i18n/{ko,en}.json`·`views/admin/RbacManagementView.vue` 메뉴 등록

### DB
- 신규 테이블 6개 — `bcp_scenarios`, `bcp_scenario_steps`, `bcp_exercises`, `bcp_exercise_steps`, `emergency_contact_groups`, `emergency_contacts`

> **기존 인스턴스**: 신규 테이블뿐이라 `ddl-auto: update` 가 기동 시 자동 생성합니다. 마이그레이션 SQL은 스키마를 명시적으로 관리하는 환경을 위한 것으로, 별도 실행 없이도 업그레이드됩니다. 기존 데이터 변경·컬럼 변경은 없습니다.

## 업그레이드 방법

```bash
docker compose build backend frontend
docker compose up -d backend frontend
```

기동 로그에서 아래 시드·RBAC 메시지를 확인합니다.

```
[RBAC] MANAGER 기본 역할에 신규 메뉴 ...: [bcp_training]
[BCP] 재해복구·BCP 훈련 시나리오 예제 7건 초기화
[RBAC] MANAGER 기본 역할에 신규 메뉴 ...: [emergency_contacts]
[비상연락망] 기본 연락 계통 6개 그룹·외부기관 연락처 4건 초기화
```

배포 후 해시된 자산 캐시 때문에 브라우저 **하드 리프레시(Ctrl+Shift+R)** 가 필요합니다.
